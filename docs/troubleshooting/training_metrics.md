# 训练指标的判读与监督

- 范围：训练日志里容易误读的指标、训练中遇到的异常、监督阈值的调整，以及评估资源的限制。
- 数据：服务器2×A100上的双卡global run（全局8192环境，世界模型10×2048窗口，策略4096条推演）。
- 日志：`train_log.csv`每50次迭代一行；`sampling_log.csv`同频，记录重置采样快照。

`sampling_log.csv`中的`samp_top1`为全局分箱权重最大值，`samp_entropy`为该权重快照的熵除以`log(max(全局分箱数, 2))`。
多卡在各自分片内再归一化，实际重置频率还受各rank重置次数影响；这两列不能直接读成某分箱占了多少实际重置。
`reset_tail_frac`才来自实际重置计数。全库不可评分时，`e0c923c`已改为可重置分箱上的均匀权重，总和为1，
修复旧版本总和不足或非有限的问题，详见[训练流程第4节](../analysis/training_pipeline.md)。

## 1. `ep_ret_norm`为负而`sim_rew`在涨

| 指标 | 平均方式 |
| --- | --- |
| `sim_rew` | 按环境步：每步奖励 / 0.1 |
| `ep_ret_norm` | 按结束回合：每回合 $`\sum_t r_t / (T \cdot 0.1)`$ |

按回合平均会放大短回合的扣分。曾经的负值来自片段末尾的极短分箱，不代表策略变差，
见[reset_sampling.md](../analysis/reset_sampling.md)与[reset_curriculum.md](reset_curriculum.md)。
**判读**：两者明显分开时，先看`sampling_log.csv`的`samp_top1`与`reset_tail_frac`，再怀疑策略。

## 2. global批量实验的学习率选择

- 现象：一次run用了`--batch_scope global --lr_scaling sqrt`，学习率为 $`2.83\times10^{-4}`$ 。
- 原因：global口径下世界模型批（10×2048）与策略批（4096）是两卡总量，与论文单卡数值相同；
  此时再乘 $`\sqrt{2}`$ 会比单卡基础学习率高 $`\sqrt{2}`$ 倍。将论文缩放理解为配合总训练批量翻倍是当前实验的推断，
  表A.5没有确认优化器批量是全局还是每卡，见[批量口径证据](../analysis/paper_two_gpu.md)。
- 解决：global口径改用`--lr_scaling none`（ $`2\times10^{-4}`$ ）。之后的run前期`wm_err8`与`imag_rew`略落后，符合学习率降低的预期。
  这是该次实验的选择；代码允许global批量搭配`none`或`sqrt`，不能由批量口径直接判定哪种符合作者设置。
- 注意：8192个环境使每次迭代的仿真数据是论文单卡的2倍，global run与论文任何一个口径都不严格对应，按小时比较耗时要打折扣。
  批量口径的两种解读见[paper_two_gpu.md](../analysis/paper_two_gpu.md)。

## 3. `wm_err8`不能和论文图3(c)比

论文对8步预测误差只有图3图注一句定义：只算状态、除以“预先设定的标称误差”、在策略rollout上在线测量，数值0.007–0.011；
标称误差的数值、第8步还是8步平均、平方还是范数都没有给。

| 项 | 论文 | 本实现`wm_err8` |
| --- | --- | --- |
| 归一化 | 固定的标称误差 | 每维除以 $`\max(\sigma_\Delta, \text{下限})`$ ， $`\sigma_\Delta`$ 是单步增量的累计标准差，达到冻结计数前随数据变化 |
| 数据 | 在线策略rollout | 回放缓冲区的训练窗口 |

`scripts/diag_wm_error.py`在新rollout上按物理单位逐分量测量，并给出几种候选标称误差下的归一化平方误差均值。
它在检查点有且`--src`源码支持时继承`gamma`、`bin_clip_end`与`bin_prior`，过渡期/末尾限制取`--src`源码的环境默认值，动作噪声由脚本独立默认0.1；
不会恢复训练中的分箱状态或自动复原全部采样参数。历史检查点的诊断应同时记录源码版本与这些条件。
8000次迭代的检查点上第8步的值：候选A（训练用的 $`\sigma_\Delta`$ ）0.156，B（`ERR_FLOOR`常数）12.6，
C（表A.2奖励尺度，只算根）0.00052，D（表A.1传感器噪声半宽）0.481。论文的标称值未知，**不能据此判定是否达到论文水平**。

## 4. 课程转向后`wm_err8`上升

- 现象：分箱覆盖完后（约1.2万次迭代），`wm_err8`从0.16升到0.45（1.55万次），世界模型损失翻倍；同期终止率从1%升到6%，
  `sim_rew`、`ep_ret_norm`、想象存活率基本不变。
- 判断依据：`wm_err8`算在最近的回放数据上（1000步缓冲区，约400次迭代）。课程把重置送到会摔的位置后，
  缓冲区里摔倒、剧烈接触的片段变多，误差自然上升。
- 验证：固定4000段子集、接近均匀的起点（新建环境、初值0、短时重放），用三个检查点各跑新rollout测第8步误差（平均/p99，物理单位）：

| 分量 | 8k | 12k | 14k |
| --- | --- | --- | --- |
| 根位置 (mm) | 2.10 / 10.2 | 1.90 / 10.1 | 1.98 / 9.5 |
| 根角速度 (rad/s) | 0.137 / 0.64 | 0.135 / 0.64 | 0.131 / 0.63 |
| 关节角RMS (rad) | 0.0067 / 0.030 | 0.0064 / 0.030 | 0.0062 / 0.027 |
| 关节速度RMS (rad/s) | 0.155 / 0.84 | 0.151 / 0.87 | 0.147 / 0.84 |

固定分布上误差持平或略降，尾部没有变差：**上升来自数据分布，不是世界模型退化**。
各检查点用自己的策略收集rollout，状态分布并不完全相同，这一点是近似。

| 迭代 | `sim_rew` | 终止率 | `imag_rew` | 策略梯度范数（裁剪前） | critic损失 | 世界模型损失 |

  世界模型没有被弄坏，只是在学那段异常数据。

- 原因未查明：可能是一次过大的策略更新，或想象rollout在难状态上的坏梯度。频繁出现时用崩溃前的检查点（`ckpt_022000`）排查。

## 6. 分箱覆盖停在78.4%

`bins_visited`的分母是全部分箱，而`reset_margin=100`下只有78.4%的分箱可作重置起点（全量79.1万个分箱）；
其余21.6%落在各片段末尾2 s内，按设计永远不会被访问。停在78.4%表示可重置分箱已全部覆盖，课程从此进入针对失败位置的阶段。

## 8. critic输入归一化很早冻结（只分析，未修改）

- `RunningNorm`是累计平均，样本数到`max_count = 2e8`即冻结，计数全局。
- critic每次迭代用33×4096 = 135,168行，约第1,480次迭代冻结（32万次的0.46%）；`last.pt`（4000次迭代）中计数为2.0005e8，已确认。
- 策略观测、目标与世界模型输入的归一化每次迭代20,480个样本，约第9,766次才冻结。
- 迭代内更新时机（先更新统计再算目标，或先算目标再更新）影响很小；冻结过早对后期的影响未知。论文没有规定critic输入归一化。

## 9. 评估与训练抢显存

- 全量参考库约39 GiB，加评估环境后单卡放不下；训练时每卡约36 GB已占用，剩余约44 GB，全量评估不能与训练同时在服务器上跑。
- 在训练卡上跑诊断：训练从2.6降到约1.7 it/s，诊断结束后恢复。全量数据的诊断有挤爆显存、打断训练的风险，改用4000段子集。
- 可选方案：把检查点拉回Rara在固定子集上评估；或等训练结束、GPU空闲后在服务器上跑全量评估。
- 传输：小检查点约72 MB，用`rsync --partial --append-verify --bwlimit=3000`断点续传，传后核对SHA256。
- `supermimic/scripts/evaluate.py`会校验数据指纹，子集与检查点的参考库不同即报错；子集评估改用
  `scripts/diag_first_step.py`，播放方式与附录F.1评估相同（逐段从首帧播放一次，摩擦1.0，无随机化与噪声）。

## 11. critic高估引发的崩溃（6.4万与9.91万次迭代）

- 现象：第四轮run（`a3c41e3`，2×A100 global）在64,000次迭代崩溃后约2,000次迭代自行恢复；99,100次迭代再次崩溃，没有恢复，
  102,750次迭代后抽样出错中止（`torch.multinomial`断言：抽样权重总和不为正，`exit.json`退出码1）。两次的日志顺序相同：critic损失先升，每步奖励随后才降。
  第二次：99,050→99,100次迭代critic损失0.011→0.168，`sim_rew`0.896→0.890；99,150起`sim_rew`降到0.757，之后继续下降。
- 诊断：`scripts/diag_critic_bias.py`让98,000、100,000、102,000次迭代的完整状态各自收集新rollout，再让三个critic交叉评估。
  98,000次迭代的策略状态（健康）上，三个critic的估值：

| critic | 估值平均 / p90 | 真实回报（平均） | 想象终点的输入梯度范数（平均） |
| --- | --- | --- | --- |
| 98,000 | 9.58 / 9.86 | 9.34 | 9.1 |
| 100,000 | 17.8 / 27.5 | 10.6 | 190 |
| 102,000 | 18.7 / 37.0 | 10.6 | 296 |

- 判断：每步奖励不超过`MAX_STEP_REWARD`（跟踪核不超过1，惩罚不为正），折扣回报与critic估值上限为`MAX_STEP_REWARD / (1 - γ)`＝10。
  崩溃前的critic准确且贴近该上限（想象推演残差+0.005）；崩溃后的critic在健康状态上也给出超过上限2–4倍的估值，输入梯度范数高出约20–30倍。
  策略目标含终点估值，梯度经它回传，因此策略更新被critic的陡度牵着走。这条因果链是对上述测量的解读，没有直接验证。
- 放大：崩溃后分箱分数降到0以下，`exp(-25·分数)`使softmax近似one-hot，单分箱权重从0.14升到0.48（102,600次迭代），回放缓冲被同一处失败填满。
- 未查明：critic最初为何高估。98,000与99,100次迭代之间没有保存任何完整状态，100,000次迭代的状态已在崩溃之后；
  诊断用2,048个环境、近似均匀的起点、一个种子。critic没有目标网络、每次迭代对自身估值做20次更新，且估值贴着上限，这只是可能的因素。
  最后一次抽样出错的原因同样没有验证：最后一条采样日志（102,750）仍是有限值，无效权重出现在其后50次迭代内。
- 防护（待在后续run中验证，不保证不再崩溃）：
  1. `--critic_cap on`（默认）：critic估值在GAE自举与策略目标里被限制在`MAX_STEP_REWARD / (1 - γ)`以内，回归仍拟合原始输出，所以高估会被拉回，策略却追不上它；对正确的critic没有影响。
  2. 分箱分数在softmax前限制到[0, 1]：范围内不变，崩溃后失败分箱并列均分40%份额。
  3. 非有限分数不更新分箱（否则一个NaN永久留在该分箱，之后所有权重计算都退回均匀分布）；非有限值也不会进入权重。
- 为下次崩溃留证据：新增`diag_log.csv`/TensorBoard的`diag/`标签（critic估值的均值、终点值、最大值、被截断比例、与GAE目标的偏差、输入偏离比例、终点输入梯度范数、
  critic梯度范数、分箱分数的均值与最小值、被跳过的非有限分数数，列的含义见README的TensorBoard一节），以及`--keep_states`（默认3）：
  `last.pt`之外保留前两次保存`last_prev1.pt`、`last_prev2.pt`。从9.8万次迭代续训的run起生效。
- 状态：这次run跑的是`a3c41e3`，没有`4293e90`与`e0c923c`的修正；没有证据表明这两项与这次崩溃有关。
  那次run的`last.pt`每2,000次迭代覆盖一次，崩溃发生后无法取回崩溃前的状态（上面的`--keep_states`就是为此加的）。
