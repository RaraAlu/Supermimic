# 复现规划：SuperMimic: Scaling Humanoid Whole-Body Control with One Differentiable World Model

- 论文：arXiv:2610.28480v1，2026-10-20提交，CoRL 2026 Oral；阅读日期2026-10-22
- 作者：Qiayuan Liao、Yiyang Shao、Junfeng Long、Kevin Zakka、Roberto Horowitz、Pieter Abbeel、Koushil Sreenath（UC Berkeley）
- 项目页：https://supermimic.github.io
- 代码发布：**无**。项目页与论文均未给出代码仓库。
- 网页演示：存在，但受专有许可约束，不能用作数据源或对照（见§4）。
- 目标层级：T2（T3列为可选）
- 用户约束：
  - GPU：Linux RTX 5080（16 GB）；Rara RTX 4070 Ti SUPER（16 GB，Windows）
  - 两张卡分属两台机器，不能直接组成论文的双卡数据并行
  - 仿真器：只能用上游MuJoCo Warp；mjwarp-rs尚无完整步进
  - 无实体G1的信息，T3实机部分默认不做

## 1. 摘要

- 目标层级为T2：在129,514段基准上，归一化回报超过0.90，且失败段数不超过179。
- 帐本共110条：PAPER 74条，INFERRED 9条，EXTERNAL 10条，UNRESOLVED 17条。
- 三大阻塞项：
  1. 世界模型状态ŝ的分量未给出（L-ARCH-2）。模型的输入、输出和损失都依赖它。
  2. 哪些预测头学习、哪些解析计算，未说明（L-ARCH-6）。它决定损失项和BPTT梯度路径。
  3. 更新数据比0.4的含义不明（L-SCHED-2）。它决定每次迭代采多少数据。
- 可行性：T1可以在16 GB卡上完成。T2全量动作库按fp32估算约45.7 GB，超出显存，需要主机流式加载或在线前向运动学（§5）。
- 第一个里程碑：M0。在Linux 5080上跑通mjlab的G1追踪任务，并实测仿真吞吐。

## 5. 算力与显存估算

以下均为估算，不是实测。

**回放缓冲（单卡）**
- 条目数：4096环境（L-SCHED-1）× 1000步（L-SCHED-3）= 4,096,000条。
- 每条下限：状态71（qpos 36 + qvel 35，L-ARCH-2的暂定值）+ 动作29 + ξ 33（L-DR-6）+ 无噪观测93（L-OBS-4，观测头若为学习头则需存）+ 奖励1 + 终止1 + 参考索引2 = 230个fp32 ≈ 920 B。
- 合计约3.77 GB。若状态还含14个追踪身体的位姿与速度（14×13 = 182维），再加约2.98 GB，合计约6.8 GB。

**动作库（全量T2）**
- 帧数：264.56 h（L-DATA-5）× 3600 × 50 Hz = 47,620,800帧。
- 每帧：关节位置29 + 关节速度29 + 14个身体×13 = 240个fp32 ≈ 960 B，合计约45.7 GB。
- 只存qpos（36维）约6.86 GB，奖励所需身体位姿改为在线前向运动学。
- 结论：16 GB卡放不下全量fp32动作库。可选方案有三：主机内存流式加载、只存qpos加在线FK、降为fp16存储。降精度存储会偏离论文，要记录在案。
- LAFAN1子集只有2.45 h（L-DATA-13），约441,000帧，约0.42 GB，可以放下。

**想象推演的激活显存**
- 每条推演每步：动力学MLP约3×2048 = 6144个激活；编码器加解码器约2×(2048+1024+512+256) = 7680个。合计约13,824个fp32 ≈ 55 KB。
- 4096条（L-OPT-6）× 32步（L-SCHED-7）× 55 KB ≈ 7.3 GB。自动微分通常还要保存激活前的值，实际可能达到10–15 GB。
- 结论：16 GB卡上偏紧。若超出，可用梯度检查点（不改变数学结果）；减小批量会偏离L-OPT-6，要记录在案。

**参数量**
- 动力学MLP：输入约133（71+29+33）×2048 + 2×2048² + 2048×71 ≈ 880万参数，很小。

**硬件差距**
- 论文用H100 80 GB（L-COMP-1）。5080与H100的TF32吞吐比，本规划不作推测，在M0实测。
- 两张16 GB卡分属两台机器，无法复现双卡9.8 h零失败（C2的T3部分）。
- 对比曲线按迭代数对齐（L-SCHED-10），不按小时对齐。
